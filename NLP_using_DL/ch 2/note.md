## 2-1 Tokenization
corpus data를 token이라는 단위로 나누는 작업이다.

token의 기준을 word로 하는 경우로, 단어 단위 외에도 단어구, 문자열로도 간주할수도 있다.

whitespace 단위로 token을 구분하면 한국어는 구분이 어려워진다.

### 5. 한국어 토큰화의 어려움
영어는 몇몇 합성어나 줄임말의 예외처리만 하면 띄어쓰기를 기준으로 단어 토큰화를 수행해도 문제가 생기지않는다.  
하지만 한국어는 띄어쓰기 단위, 즉 어절을 기준으로 토큰화하면 조사, 어미 등이 붙은 교착어이기때문에 제대로된 정제가 어렵다.

- 교착어의 특성
한국어는 조사가 존재한다. 그(he)라는 주어나 목적어가 들어간 문장을 예시로하면 '그가', '그를', '그와', '그는' 등의 조사들이 '그'라는 단어에 붙어있는 형태이다.
서로 다른 조사가 붙으면 다른 단어로 인식 될수도 있기때문에 어절 단위로 토큰화하지않고 조사를 분리해야한다.

>형태소(morpheme): 가장 작은 말의 단위  
>- 자립 형태소: 접사, 어미, 조사와 상관없이 자립하여 사용할 수 있는 형태소. 체언(명사,대명사,수사), 수식언(관형사, 부사), 감탄사 등이 있다.  
>- 의존 형태소: 다른 형태소와 결합하여 사용되는 형태소. 접사, 어미, 조사, 어간이 이에 포함된다.  
>
>ex) 에디가 책을 읽었다  
>1) 단위 토큰화 
>['에디가','책을','읽었다']
>2) 형태소 단위 분해
>자립 형태소: 에디, 책
>의존 형태소: -가, -을, 읽-, -었, -다

- 한국어는 띄어쓰기가 영어보다 잘 지켜지지않는다  
한국어는 띄어쓰기가 지켜지지않아도 글을 쉽게 이해할 수 있는 언어이다.

## 2-2 Cleaning & Normalization
- 정제: corpus로부터 노이즈 데이터를 제거한다
- 정규화: 표현 방법이 다른 단어들을 통합시켜 같은 단어로 만든다.

### 1. 규칙에 기반한 표기가 다른 단어들의 통합
USA와 US, uh-huh와 uhhuh처럼 형태는 다르지만 같은 의미를 같은 단어들을 통합시키는 것을 정규화라고한다.  
이때 뒤의 단어들을 통합하는 방법은 어간 추출(stemming)과 표제어 추출(lemmatization)이 있다.

### 2. 대, 소문자 통합
대, 소문자를 통합하는 것은 정규화의 한 방식이다.  
문단의 첫 단어로 Picture가 나왔고 중간에 같은 의미로 picture가 나왔을때 picture를 찾는 과정에서 결과로 Picture를 찾을 수 있게한다.

하지만 대, 소문자를 모두 통합하는 행위또한 위험하다. 왜냐하면 미국을 뜻하는 US와 우리를 뜻하는 us는 의미가 다르고 대소문자만 다르기때문에 통합하지않고 구분해야한다.

### 3. 불필요한 단어의 제거
노이즈 데이터는 자연어가 아니면서 의미를 갖지 않는 글자(특수 문자 등)을 의미하기도하고, 분석하는 목적에 맞지않는 불필요한 단어들을 모두 포함하는 개념이다.

불필요한 단어를 제거하는 방법으로는 불용어 제거와 등장 빈도가 적은 단어, 길이가 짧은 단어들을 제거하는 방법이 있다.
불용어 제거는 추후 챕터에서 다룰 예정이다.

- 등장 빈도가 적은 단어
corpus에서 너무 적게 등장해서 도움이 되지않는 단어들을 제거하는 방법이다.

- 길이가 짧은 단어
한국어에서는 유효하지않지만 영어권 언어에서는 길이가 짧은 단어를 삭제함으로써 성능을 높일수있다.  
영어에서 유효한 이유로는 일반적으로 영어 단어 평균 길이는 6-7자 정도이다. 이때 2-3자 이하의 단어는 중요한 의미를 담지 않을 가능성이 높기때문에 대부분의 불용어가 제거될 수 있다.

### 4. 정규 표현식
corpus에서 노이즈 데이터의 특징을 특정할 수 있게되면, 정규 표현식을 통해서 제거할 수 있다.  
예를 들어 HTML 문서에서는 HTML 태그가 존재할 것이고, 뉴스 기사에서는 개제 시간 등의 노이즈 데이터가 존재할 것이다.  
이 데이터들의 특징을 정규 표현식으로 한번에 제거할 수 있다.

## 2-3 Stemming & Lemmatization
표제어 추출(lemmatization)과 어간 추출(stemming)의 개념은 서로 다른 언어들이 담고 있는 의미가 같으면 하나의 단어로 일반화시켜서 corpus 내의 단어 종류를 줄이는 방법이다.

### 1. 표제어 추출
표제어는 한글로 '기본 사전형 단어'라고 쓸수도 있다.  
표제어 추출은 단어들이 표제어를 찾아가는 과정을 뜻한다.  
예시로 am, are, is 등은 형태는 달라도 모두 be에서부터 시작하였다. 그렇기때문에 이 단어들의 표제어를 be라고 한다.

표제어 추출을 하는 방법은 단어의 형태학적 파싱을 먼저 하는 것이다.  
형태학이란 형태소로부터 단어를 만들어 가는 학문을 뜻한다.  
형태소란 '의미를 가진 가장 작은 단위'를 뜻하고 종류로 어간과 접사가 존재한다.
```
어간
:단어의 의미를 담고있는 단어의 핵심 부분

접사
:단어에 추가적인 의미를 주는 부분
```

### 3. 한국어에서의 어간 추출
한국어의 체계 5언 9품사
| 언 | 품사 |
| 체언 | 명사, 대명사, 수사|
| 수식언 | 관형사, 부사 |
| 관계언 | 조사 |
| 독립언 | 감탄사 |
| 용언 | 동사, 형용사 |

이중 용언에 해당하는 동사와 형용사는 어간과 어미의 결합으로 구성되어있다.

> 1) 활용 
> 활용이란 용언의 어간이 어미를 가지는 것을 말한다.
>  - 어간: 용언을 활용할 떄, 원칙적으로 모양이 변하지 않는 부분(때로 어간의 모양이 바뀔수도있다.)
>
>  - 어미: 용언의 어간 뒤에 붙어서 활용하며 변하는 부분(문법적 기능을 수행한다.)
>
>
> 2) 규칙 활용
> 어간이 어미를 취할 때, 어간의 모습이 일정함을 규칙 활용이라 한다.
> ```
> 잡(어간) + 다(어미)
> ```
> 어간이 어미가 붙기 전/후가 같으므로 어미를 분리하면 어간 추출이 된다.
> 
> 
> 3) 불규칙 활용
> 어간이 어미를 취할 떄, 어간의 모습이 바뀌는 특수한 상황을 불규칙 활용이라 한다.
> 예시로 '듣다'와 '들리다'처럼 어미에따라 어간의 형태가 바뀌므로 불규칙 활용에 속한다
> 이러한 경우에는 어미를 분리하는 단순한 작업만으로 어간 추출이 되지않고 좀더 복잡한 규칙을 필요로한다

## 2-5 정규 표현식

### 1. 정규 표현식 문법과 모듈 함수
파이썬에는 정규 표현식 모듈로 re를 지원한다.

- 정규 표현식 문법
| 특수 문자 | 설명 |
| . | 한 개의 임의 문자를 나타낸다. |
| ? | 앞의 문자가 존재할 수도, 안할수도 있다.(문자가 0또는 1개) |
| * | 앞의 문자가 무한하게 존재할 수도, 안할수도 있다.(문자가 0이상의 자연수) |
| + | 앞의 문자가 최소 1개 이상 존재한다.(문자가 1개 이상의 자연수) |
| ^ | 뒤의 문자열로 문자열이 시작된다. |
| $ | 앞의 문자열로 문자열이 끝난다. |
| {숫자} | 숫자만큼 반복한다. |
| {숫자1, 숫자2} | 숫자1 이상, 숫자2 이하만큼 반복한다.(?,*,+로 대체가 가능) |
| {숫자,} | 숫자 이상만큼 반복한다. |
| [문자] | 대괄호 안의 문자 중 하나라도 일치하는지 매치한다. [amk]라고 하면 a,m,k 중 하나라도 존재하면 1이다. [a-z]처럼 범위를 지정할 수도 있다 |
| [^문자] | 해당 문자를 제외한 문자를 매치한다. |
| \| | A\|B로 사용하며 A 또는 B라는 의미를 가진다. |

| 문자 규칙 | 설명 |
| \\\\ | 역슬래시 문자 하나를 출력한다 |
| \\d | 모든 숫자를 의미한다.([0-9]) |
| \\D | 모든 숫자를 제외한 문자를 의미한다.([^0-9]) |
| \\s | 공백을 의미한다.([ \\t\\n\\r\\f\\v]) |
| \\S | 공백을 제외한 문자를 의미한다.([^ \\t\\n\\r\\f\\v]) |
| \\w | 문자와 숫자를 의미한다.([a-zA-Z0-9]) |
| \\W | 문자와 숫자를 제외한 문자를 의미한다([^a-zA-Z0-9]) |

- 정규 표현식 모듈 함수
| 모듈 함수 | 설명 |
| re.compile() | 정규 표현식을 컴파일하는 함수이며, 찾으려는 패턴이 많을 경우 미리 컴파일해놓고 사용하면 속도와 편의성에서 유리하다. |
| re.search() | 문자열 전체에대해 정규 표현식과 매치되는지 검색한다. |
| re.match() | 문자열의 처음이 정규 표현식과 매치되는지 검색한다. |
| re.split() | 정규 표현식을 기준으로 문자열을 분리하여 리스트로 리턴한다. |
| re.findall() | 문자열에서 정규 표현식과 매치되는 모든 경우의 문자열을 찾아서 리스트로 리턴한다. |
| re.finditer() | 문자열에서 정규 표현식과 매치되는 모든 경우의 문자열에 대한 이터레이터 객체를 리턴한다. |
| re.sub() | 문자열에서 정규 표현식과 일치하는 부분을 다른 문자열로 대체한다. |

## 2-8 One-Hot Encoding
원-핫 인코딩을 위해 먼저 단어 집합을 만들어야한다.  

- 단어 집합: 서로 다른 단어들의 집합(book과 books같이 변형 형태도 다른 언어로 간주한다.)

### 1. 원-핫 인코딩
원-핫 인코딩은 단어 집합 크기를 벡터의 차원으로 변환하고, 표현하고 싶은 단어의 인덱스에 1을 대입, 나머지는 0을 대입하는 벡터 표현 방식이다.

### 3. Limit of One-Hot Encoding
원-핫 인코딩과같은 방식은 단어 집합에 들어갈 단어의 수가 늘어날수록 필요한 공간이 급격하게 늘어난다는 단점이 존재한다.  
이를 다른 표현으로는 벡터의 차원이 늘어난다고 표현할 수 있으며, 즉 '단어 집합의 크기'='벡터의 차원 수'가 된다.  

원-핫 인코딩의 벡터는 단어의 유사도는 표현하지 못한다는 단점이 존재한다.  
이러한 단점은 검색 시스템에서 문제가 될수도있다. 예를 들어 '삿포로 숙소'를 검색했을때 '삿포로 게스트 하우스'나 '삿포로 료칸'과같은 유사 단어간의 유사성을 계산할 수 없다.

위의 문제점들을 해결하기위해 단어의 잠재 의미를 반영하여 벡터화하는 기법이 크게 두 가지가 있다.  
첫째는 카운트 기반의 벡터화 방법인 LSA(잠재 의미 분석),HAL 등이 존재한다.  
둘째는 예측 기반으로 벡터화하는 NNLM, RNNLM, Word2Vec, FastText 등이 존재한다.  
또한 이 두 방식을 모두 채택하는 GloVe라는 방법도 있다.


## 2-9 Splitting Data

### 1. 지도 학습(Supervised Learning)
지도 학습의 훈련 데이터는 '문제'에 해당하는 데이터와 '정답'에 해당하는 레이블로 구성되어있다.  
이때 데이터와 레이블을 대조하며 학습하고, 레이블이 존재하지않는 문제 데이터의 정답을 예측하는 것을 지도 학습이라고 한다.  

데이터와 레이블을 각각 x와 y로 저장한 후 이 데이터를 다시 분리해야한다.  
X_train, Y_train, X_test, Y_test로 분리하면 train 데이터로 학습을 한다.  
그리고 test 데이터로 정답을 예측 시킨 후 실제 답과 비교하여 평가한다. 이 수치가 accuracy가 된다.
